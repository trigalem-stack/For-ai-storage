## 2. Тестовый стенд

Тестовый плагин `tests/FixTest.java` строит в мире (на высоте 250, вне территории) такую сцену:

* каменный пол с верхом **y = 250** для `x = 0..13`, `z = 0..11` (край обрыва на `x = 14`);
* «низкая земля» с верхом **y = 247** для `x = 14..30`, `z = 6..11` (обрыв высотой 3);
* парящая стена 2 блока высотой на `x = 22`, `z = 0..5` (`y = 250..251`);
* одиночный блок на полу в `(5, 250, 5)`;
* снежное облако 3×3 (`SNOW_BLOCK`, верх **y = 250**) в `x = 16..18`, `z = 2..4`.

Через reflection вызываются `computeDestination(World, Location)` у DragonKatana и
`predict(World, x, y, z, vx, vy, vz, supported, lead=4)` у SkySwordPlugin.
Сырой вывод сервера — `tests/test-output.log`.

## 4. Небесный меч — предсказание приземления (`predict`, lead = 4 тика)

Формат результата: `x / y / z` предсказанных ног через 4 тика и `leave` — тик, на котором игрок теряет опору
(`-1` — не теряет в пределах горизонта, `0` — уже в воздухе). `null` — снег не нужен (траектория и так
приземляется на существующий блок / упирается в стену).

| # | Ситуация | Результат | Ожидание | Итог |
|---|----------|-----------|----------|------|
| S1 | бег (+x 0.28/тик) в 5 блоках от края | `10.12 / 250.00 / 2.50`, leave −1 | снег не ставится | ✓ |
| S2 | бег, 1 блок до края | `14.12 / 249.92 / 2.50`, leave **4** | leave = ping/50+2 → **снег заподлицо** впереди, без провала | ✓ |
| S3 | бег, уже на краю | `15.02 / 249.23 / 2.50`, leave 1 | leave < 4 → снег **на 1 блок ниже** точки приземления (y=248, верх 249) | ✓ |
| S4 | край над низкой землёй (−3) | `null` | снег не нужен — упадёт на землю | ✓ |
| S5 | падение над обрывом (−0.5/тик) | `21.62 / 249.33 / 2.50`, leave 0 | снег на y=248 (верх 249) под предсказанной точкой | ✓ |
| S6 | падение над низкой землёй | `null` | снег не нужен | ✓ |
| S7 | прыжок на месте (сервер считает игрока на земле) | `5.50 / 250.00 / 2.50`, leave −1 | не теряет опору → снег не ставится | ✓ |
| S7b | прыжок на месте (в воздухе, vy = +0.42) | `null` | приземлится обратно на пол в пределах 14 тиков → снег не ставится | ✓ |
| S8 | прыжок к краю, уже в воздухе | `null` | траектория ложится на снежное облако стенда → снег не нужен | ✓ |
| S9 | бег по облаку к его краю | `19.62 / 249.54 / 3.50`, leave 2 | снег на 1 блок ниже, под точкой схода | ✓ |
| S10 | ходьба в стену-блок | `null` | упирается → снег не ставится | ✓ |
| S11 | спринт по ровному полу (до края далеко) | `6.12 / 250.00 / 2.50`, leave −1 | снег не ставится | ✓ |
| S12 | быстрое падение (−1.0/тик) над обрывом | `20.50 / 250.43 / 2.50`, leave 0 | снег на y=249 (верх 250) — игрок долетит до него через ~4 тика | ✓ |
| S13 | бег по облаку в сторону обрыва | `17.50 / 249.77 / 1.48`, leave 3 | снег на 1 блок ниже | ✓ |
| S14 | спринт, 2 блока до края (7 тиков) | `13.12 / 250.00 / 2.50`, leave −1 (край дальше lead) | снег не ставится — ещё рано | ✓ |

То есть: пока до края больше `ping/50 + 2` тиков — снег **уже ставится заподлицо** впереди (S2),
игрок сходит на готовое; если времени нет (S3, S9, S13) — ставится на блок ниже предсказанной точки,
и клиент не оказывается внутри блока; на готовой поверхности / при обычном прыжке / над землёй кубики не тратятся (S4, S6, S7b, S11, S14).

## 5. Ограничения проверки

* Нет клиента: реальный тайминг при спринте и вашем пинге, а также плавность ходьбы по облаку нужно
  проверить в игре. Алгоритм подстраивается под `Player#getPing()` автоматически (упреждение = ping/50 + 2 тика).
* Скорость игрока измеряется по пакетам движения (`PlayerMoveEvent`); при резких рывках/лагах оценка
  сглаживается, поэтому первый кубик после рывка может встать на блок ниже.
* Снег по-прежнему живёт 5 секунд (100 тиков) и исчезает с частицами — как в оригинале.
